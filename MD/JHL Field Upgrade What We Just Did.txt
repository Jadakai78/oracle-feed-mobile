2. Gave Gimba a consensus + offense-mode brain
We upgraded scanner.py (Gimba) to respect agreement and field type, instead of treating every WATCH the same.

2.1 Consensus buckets
New helper in scanner:

python
_consensus_bucket(row) -> str
It looks at all four bots (VOL/RNG/RTS/TRD) and returns:

all_4 – all four in same direction.

three_of_4 – three bots aligned.

two_of_4 – two aligned.

split – BOTH long and short firing.

solo – only one bot active.

none – no WATCH bias.

This is the “common indication” language you wanted: how many specialists are saying the same thing.

We use it to scale conviction:

all_4 / three_of_4 → conviction * 1.25, capped at 1.0.

two_of_4 → conviction * 1.10.

split / solo → conviction * 0.70.

2.2 Offense modes
New helper:

python
_offense_mode(row) -> str
It uses structure, tempo, trap, and volume to classify the field type:

dead – STRUCTURE_UNCLEAR + most tempos DEAD.

trap_mode – high trap_score or very thin rvol.

trend_mode – TRENDING_* structure states.

range_mode – RANGING_NEUTRAL.

mixed – everything else.

We then apply mode-specific rules:

dead:

All bots: action_state = idle, conviction = 0.

trap_mode:

All bots: conviction *= 0.70 (shielded).

trend_mode:

TREND & VOL can run.

RNG allowed but only at edges; otherwise conviction *= 0.60.

range_mode:

RNG favored.

TREND trimmed: conviction *= 0.60.

This is your offense plan: how we attack (or don’t) in each kind of field.

3.2 gimba_trend.evaluate_with_knn(...)
We added a wrapper to gimba_trend.py:

python
def evaluate_with_knn(pair, kraken_pair, current_price, fg_score=50, log_dir=None) -> dict:
    result = evaluate(...)
    engine = KNN("gimba_trend", log_dir, min_samples=30)
    adj, n = engine.adjust(result)
    if n >= 30:
        result["conviction"] = clamp(raw + adj)
        result["knn_adj"] = adj
        result["knn_samples"] = n
    else:
        result["knn_adj"] = 0.0
        result["knn_samples"] = n
    return result
